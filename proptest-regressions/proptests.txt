# Seeds for failure cases proptest has generated in the past. It is
# automatically read and these particular cases re-run before any
# novel cases are generated.
#
# It is recommended to check this file in to source control so that
# everyone who runs the test benefits from these saved cases.
#
# READ THIS BEFORE TRUSTING A LINE BELOW.
#
# A `cc` line is a seed for the *generator*, not a saved case: proptest replays its RNG with
# that seed, so the sequence it produces depends on what the strategy looks like today. Edit
# `op_strategy` — add an operation, reorder the arms — and the same seed produces a *different*
# sequence, and the line silently stops guarding the regression it was saved for while still
# reading like protection.
#
# That is not a hypothesis, it is measured. The seed saved on P7 (`46170ffe`, property
# `collapsed_counts_stay_derived`, shrunk to a three-step collapse) was checked on P13 after the
# vocabulary of operations moved to `core::testkit`: with the P7 fault put back
# (`node_update_collapsed` walking one ancestor instead of all) and `PROPTEST_CASES=0`, so that
# only the seeds in this file ran, the property passed. The same fault is caught by random cases
# and, deterministically, by the named unit test
# `removing_a_collapsed_leaf_updates_ancestor_counts` — so the seed was deleted rather than left
# here as a promise the file does not keep.
#
# The rule that follows: a seed is cheap insurance, never a substitute for a named `#[test]`.
# When a property finds something worth keeping, write the case down as a test — as was done on
# P7 and P8 — and treat whatever lands here as a bonus that expires the next time the generator
# changes.
